# Практическая работа №6. От накопителя до процессора: как запускается программа

## Цель работы
Исследовать жизненный цикл программы от момента её хранения на накопителе до выполнения инструкций процессором, изучить параметры процессов (PID, WorkingSet) через Диспетчер задач.

## Результаты исследований

### Шаг 2. Где находится программа до запуска
- **Путь к папке bin:** `Lab06/bin/Debug/net6.0/`
- **Какие файлы появились после сборки:** `Lab06.exe` (главный исполняемый файл), `Lab06.dll` (компилированный байткод программы), `Lab06.runtimeconfig.json` (конфигурация среды .NET) и `Lab06.pdb` (отладочные символы).

### Шаг 3 и 5. Параметры запущенного процесса
- **Название процесса:** `Lab06` (или `dotnet`)
- **PID (Ид процесса):** `4152` (динамический идентификатор ОС)
- **Память по данным программы (WorkingSet64):** 28 МБ
- **Память по данным Диспетчера задач:** ~28.4 МБ

**Вывод о состоянии процесса после закрытия программы:**
Когда программа завершает свою работу, её процесс полностью исчезает из таблицы Диспетчера задач, а выделенная под него оперативная память (RAM) освобождается операционной системой для нужд других приложений.

### Шаг 6. Нагрузка при вычислениях
- **В простое (ожидание ввода):** Память ~28 МБ, загрузка процессора (CPU) равна 0%.
- **Во время вычислений (цикл 10 секунд):** Память практически не изменяется (~28 МБ), но загрузка CPU резко подскакивает до 25% (ровно одно логическое ядро из четырех полностью забивается математическим циклом).

### Шаг 8. Накопитель компьютера
- **Тип накопителя на учебном ПК:** SSD (модель Kingston A400).
- **Влияние на скорость:** Твердотельные накопители (SSD/NVMe) считывают исполняемые файлы программы в оперативную память в несколько раз быстрее старых жестких дисков (HDD), что сильно ускоряет первоначальный запуск системы и софта.

### Итоговый эксперимент: сравнение параметров в простое и под нагрузкой
1. **До запуска вычислений:** Память ~28 МБ, Нагрузка ЦП: 0%.
2. **Во время вычислений:** Память ~28 МБ, Нагрузка ЦП: 25%.

**Главный вопрос:** Почему изменяется использование памяти и загрузка процессора во время вычислений?
**Ответ:** Загрузка процессора растет, потому что ядра CPU начинают непрерывно выполнять миллионы математических операций сложения и умножения в цикле. Использование памяти при этом не растет, так как количество переменных в коде остается фиксированным (переменные `result` и `i` занимают одни и те же ячейки в RAM, новые объекты в памяти во время цикла не создаются).

## Ответы на контрольные вопросы

1. **Чем файл программы на HDD/SSD отличается от работающего процесса?**
   Файл на HDD/SSD — это пассивный набор байт (инструкций), который просто хранится на диске без потребления энергии и ресурсов CPU. Работающий процесс — это уже копия этой программы, развернутая операционной системой в оперативной памяти, которая активно потребляет ресурсы процессора и выполняет команды.
2. **Зачем программе нужна оперативная память после запуска?**
   Процессор не умеет напрямую выполнять код с медленного HDD/SSD накопителя. После запуска ОС полностью копирует инструкции программы в быструю оперативную память (RAM), чтобы ядра CPU могли считывать команды на огромной скорости без задержек.
3. **Как по Диспетчеру задач можно увидеть, что программа действительно работает?**
   Во-первых, она появляется в списке активных процессов на вкладке «Подробности» или «Процессы». Во-вторых, в реальном времени видно, что она забирает под себя ненулевой объем ОЗУ и создает нагрузку на CPU на вкладке «Производительность».
4. **Почему во время вычислений увеличивается загрузка CPU?**
   Потому что поток программы заставляет логическое ядро процессора непрерывно крутить тяжелый математический цикл, выполняя арифметические операции без пауз.
5. **Остается ли файл программы на HDD/SSD после завершения процесса?**
   Да, файл на накопителе остается абсолютно нетронутым. Процесс — это лишь временная копия программы в ОЗУ. При закрытии софта уничтожается только эта копия в RAM, а исходный файл на диске может храниться годами.

## Итоговый вывод
В ходе работы был исследован весь путь запуска программы от накопителя до процессора по цепочке: `HDD/SSD -> RAM -> процесс -> CPU`. На практике доказано, что операционная система полностью изолирует исполняемый файл от активного процесса в памяти, а сам процесс динамически утилизирует ресурсы процессора только в моменты активных вычислений, полностью освобождая их после закрытия приложения.
